# 最小实验方案：1 天与 7 天查询的 Parquet 排序回本点

状态注记（2026-11-17）：下文保留预试验时的历史计划；正式实验已按另存的《正式实验执行清单》完成，结果见 results/formal/formal_20261117_01/。不写报告，不实现自动选择器。

## 研究问题

同一份 30 天的模拟观测数据，查询窗口由 1 天扩大到 7 天后，按时间排序所节省的查询耗时及抵消重排成本所需的查询次数是否改变？结论仅适用于所测数据分布、查询及运行条件。

## 控制条件

- 数据内容、字段与类型、随机种子、观测总时间范围一致。记录含唯一 ID、观测时间、站点、经纬度整数表示、摄氏温度的百分之一整数表示。模拟字段用于性能实验，不推断真实海洋规律。
- 两种布局：观测时间伪随机分布的原文件；同一文件按 event_time、observation_id 排序后的文件。
- 相同 Parquet 写出引擎、ZSTD 级别 3、行组目标 65,536 行、单文件、单查询线程、1 GB 引擎内存上限。核对实际行组行数。
- 排序可自然改变压缩后文件大小；记录大小，不强制等长。性能差异不能全部归因于裁剪。
- 同一机器、同一 DuckDB 版本、同一 SQL 结构。时间使用无时区的统一时间轴，窗口左闭右开。
- 两种窗口采用相同 7 个起点：6 月 1、5、9、13、17、21、24 日；全部落在 30 天数据范围内。两种布局对同一窗口必须回答相同问题。
- 计时范围为 execute 到 fetchone 完成，包括固定的 SQL 处理开销。显式预热，不清系统缓存，不声称冷启动或真实磁盘读取性能。

## 改变条件

布局：乱序、时间排序。窗口长度：1 天、7 天。形成四个条件。日期起点作为重复覆盖因素，两种窗口共用起点。

预试验从 100 万行开始。正式实验的数据量只能在检查计时稳定性后确定，暂不直接扩大或正式运行。

## 正确性

1. 两份文件均核对总行数与唯一 ID 数。
2. 对唯一 ID 作全外连接，逐字段比较，全量缺失或不同记录必须为 0。
3. 每个时间窗口分别比较 count 与整数温度 sum，要求完全相等；平均温度要求 abs_tol=1e-10 摄氏度、rel_tol=1e-12 内一致。
4. 不比较 1 天与 7 天结果是否相同；只比较相同窗口在两种布局下的结果。

## 预试验计时与稳定性标准（运行前确定）

- 每种窗口 9 轮配对测量，布局执行顺序交替；每轮每种布局执行相同的 35 次查询（7 个起点各 5 次，随机顺序相同）。保存每轮总耗时及单次均值。
- 以 9 个批次均值的中位数汇总。35 次循环不当作 35 个独立样本。
- 两种布局的批次均值 IQR/中位数均不超过 20%，视为此轮计时波动可接受。
- 至少 8/9 轮差异方向一致，且配对差值中位数的 bootstrap 95% 区间不跨 0，视为初步可分辨差异。仅为探索性稳定性检查，不是正式统计推断或预设加速标准。
- 第一轮合格后用新进程再跑一次同规模确认；不删除慢轮次。若明显抖动，先增加每批计时长度或排查背景负载。不能为追求加速而反复调整设置。
- 元数据可跳过行组比例作为解释依据，明确为 min/max 推算，不冒充真实读取字节或引擎实测 I/O。

## 排序成本和回本点

重排 R = 读取原文件 + 排序 + 写出排序文件。重复写出 3 次，逐次记录；中位数用于预试验估算，首次成本单独保留。计时到 COPY 返回，不宣称已经完成硬件持久化 fsync。原始数据生成成本不计入任何一方新增成本。

窗口 w 的每次节省为 Δ_w=t_乱序,w-t_排序,w。正且稳定时，估计回本次数为 ceil(R/Δ_w)。1 天与 7 天共用同一个 R，不将排序成本重复收取。若节省为 0 或负数，报告在此条件下没有观察到有限回本点。

预试验回本点只是代数估计，不是验证结果。正式实验另用未参与估计的窗口起点测累计查询耗时，比较 T_乱序(N) 与 R+T_排序查询(N)，检查回本点附近的判断；不把预试验中已经看到的结果称为事前预测。

## 数据量选择规则

两次同规模预试验均通过正确性、波动标准，并表现出可重复的差异方向，则可保留该规模用于正式实验。若时长过短、波动大，可扩大计时批次或数据量，但记录原因。若差异稳定接近零，也接受该发现，不以必须得到加速为选规模条件。

## 预试验后的范围决定

2026-11-17 已完成两次独立进程的 100 万行预试验。两次均通过全部正确性断言；两种查询窗口均在 9/9 配对轮次中观察到排序文件更快；各组 IQR/中位数低于 4%，配对差值 bootstrap 区间均为正。根据预定规则，正式实验采用 100 万行，不追加更大规模以追求更大加速比。

后续正式实验预定：保持本方案所有控制条件，验证查询使用新的起点偏移 [2,6,10,14,18,22] 天（6 月 3、7、11、15、19、23 日），分别查询 1 天和 7 天。每种窗口测 N=[1,10,20,30,50,100] 次累计查询；每个 N 的查询序列提前固定、两种布局共用，单独预热不计入 N；每个条件重复 5 次并交替执行顺序。总时间明确由一次重排 R 加上实测累计查询时间构成，不能用单次耗时直接相乘冒充累计实测；保留重排 3 次的全部成本以检查回本点对 R 波动的敏感性。预试验估计约 24 次（1 天）和 30–31 次（7 天），仅用于安排交点附近的 N，不当作正式验证结果。

这些正式实验尚未执行。两种窗口的正式结果允许更快、接近打平或更慢。预热代价不属于本实验的稳态比较；本实验不评价首次打开数据时从零开始的全部端到端成本。小规模取样、自动布局选择、真实 AIS/海温数据获取及报告写作均不在本轮范围内。
