# 报告提纲与证据映射（讨论稿）

日期：2026-11-18。用途：确定论证范围、章节问题和证据位置；不是完整报告。本轮不新增实验，也不将待讨论的补充方案写成已完成工作。

建议题目：**模拟海洋观测表的 Parquet 排序收益边界：1 天与 7 天查询的累计成本实验**。

## 一、研究定位和原创性边界

目前是一项范围明确的经验性探索，已有独立设计的对照实验和可复核数据，不是新算法、自动选择器或行业首创方法。老师允许原创性延伸或实验验证，因此它有成为课程研究报告的基础；能否达到教师期望的创新程度不能保证。

可声明的贡献：针对固定模拟观测表，独立比较两种窗口长度下的累计成本；通过整批计时验证回本位置；区分净节省转正和达到人为约定收益幅度的次数；保存计划、数据一致性证据、所有计时和标准修正记录。

不能声明的贡献：发明排序裁剪、首次考虑重排成本、发明 10% 门槛、提出新的回本公式、验证了可部署的自动优化器。代码可复现和记录透明属于研究质量，不自动等于方法创新。

## 二、报告提纲：每节的问题与证据

### 1. 问题背景与研究范围

要回答：为什么“排序后单次查询更快”不足以回答“这批任务值得排序吗”？为什么比较 1 天和 7 天窗口？

内容边界：说明海洋观测表的时间范围查询场景；提出时间窗口长度和查询重复次数共同影响累计收益的问题。显著位置预留实际的公开 GitHub 仓库链接；目前仓库尚未创建或上传，不能写成已完成。

引用：课程幻灯片及上述 DuckDB 官方资料；已有研究使用 OReO。当前不需要结果图，防止以结果代替问题定义。

### 2. 已有方法与本次具体研究问题

要回答：哪些原理已经存在？我们实际探索什么未知量？

研究问题 RQ1：在固定文件和暖缓存条件下，查询窗口从 1 天变为 7 天，整批累计成本与净节省转正的位置怎样改变？

研究问题 RQ2：在同一数据上，刚抵消排序成本和总时间降低至少 10%，对应的已测次数是否不同？

补充问题 RQ3：用历史预试验输入构造的简单成本预测，与正式实测相差多少？此项只能列为事后补充复核。

引用：本提纲的来源分类表；正式冻结配置的 `frozen_pilot_estimates` 和 `pilot_sources`（文件 D1）。避免声称“选择性越低回本必然越晚”，现有只测了两个长度。

### 3. 数据、变量和实验环境

要回答：使用什么数据、改变了什么、控制了什么？这些条件为什么足以对比而又不足以推广？

应列：100 万行、30 天、伪随机时间、6 个字段、模拟温度；乱序与 event_time/observation_id 排序；DuckDB 2.0.0；1 个查询线程、1 GB 引擎内存上限；ZSTD 级别 3、行组目标 65,536 行，实际 16 个行组；一份文件一种布局；统一预热。两个文件约 16.67 MB 和 16.03 MB，可被系统缓存，不能称为超内存大数据场景。

引用：D1（配置）、D2（准备和元数据）、C1（生成代码）、C2（正式代码）。可做一张“控制变量表”，不用新增实验图。

### 4. 指标、实验流程和正确性

要回答：累计时间是否实际执行得到？排序成本如何计入？如何证明两种布局回答同一个问题？如何避免事后改标准？

指标：T_A(N) 是真实执行 N 次原文件查询的时间；T_B(N)=R+Q_B(N)，其中 R 和 Q_B 都是实测，但不是一个从排序到结束的连续计时区间。R 主值用本轮三次重排中位数；展示三次成本的敏感性。

百分比：每轮 g=100*(T_A-T_B)/T_A，再取五轮中位数。净节省 g>0 与至少 10% 的 g>=10 分开；-10%<g<10% 归为接近打平。10%/20% 是操作性约定，不是统计显著性标准。

流程：先冻结配置和序列；新起点不参与估计；19 种 N、2 种窗口、每组 5 轮；同一轮各 N 取同一序列前 N 条；布局顺序交替，条件顺序随机；整批 perf_counter_ns 计时；结果验证在计时外；所有轮次保留。

正确性：100 万行及唯一 ID 数均相同；全外连接逐字段差异为 0；相同窗口 count、整数温度 sum 相等，avg 按容差核对；计时中每次返回值核对。

计划差异必须披露：10%/20% 曾在聊天中提前约定，但正式冻结执行文件主要登记零收益交点，最初总结遗漏 10% 分档。后续审计恢复该门槛并保留原结果。不能声称完整评价方案从一开始就无遗漏地预先登记。

引用：D1、D2、D3、D4、D7；图形阴影为五轮 min/max，不是置信区间。11,880 次查询是重复计时调用数，并非 11,880 种独立场景。

### 6. 机制解释与适用边界

要回答：观察到的差异与候选行组数是否相符？哪些解释仍未被单独验证？

### 7. 事后补充：预测误差与分析口径审计

要回答：20% 误差是否检查过？预测输入何时产生？现有补充结果能支持什么、不能支持什么？

如实写：正式第一版没有做误差检查；虽然保存了两轮预试验 R 和 t_B，但没有预存逐 N 预测表，也没有指定唯一主预试验。补充审计分别使用两组既有输入计算 R_pilot+N*t_B,pilot，不把正式 R 或正式查询时间输入预测；正式结果仅用于误差评价。

相对误差=abs(预测-实测)/实测。对各 N 的五轮总耗时中位数比较，两轮预试验来源对应的最大误差分别为：1 天 7.11%/3.98%，7 天 4.36%/2.19%。这些数值支持“这次补充复核低于 20%”，不支持“已完成严格事前预测验证”或“可自动预测任意数据”。

## 三、必须写进报告的适用范围与不足

1. 模拟观测表：时间和其他字段按伪随机规则生成，没有真实海洋数据的季节性、缺测、时间倾斜和变量相关性。海洋场景提供问题语境，没有验证海洋专用算法。
2. 固定规模与环境：只测 100 万行、一个种子、一个 DuckDB 版本、一台电脑、单线程、一组压缩和行组设置。不能外推到云对象存储、分布式系统或 TB 数据。
3. 暖缓存重复查询：预热、连接初始化等开销不计入批次，未清系统缓存。不是首次使用从零开始的全部端到端开销。
4. 排序计时到 COPY 返回：包括读取、排序和写出；没有验证硬件持久化 fsync。主结果固定使用三次 R 的中位数，不包含任意未来重排的全部成本不确定性。
5. 验证起点与预试验不同，但使用同一底表且时间窗口可能重叠，不能称为独立数据集测试。六个窗口也不是覆盖整个日期空间的随机样本。
6. 五轮足以展示本次波动，不构成普遍稳定性的证明；反复查询少量窗口不能扩大成独立样本数量。
7. 日期与行组边界覆盖不全，当前候选组数集中在 1/4，机制解释尚缺有针对性的对照。
8. 压缩大小也变化，候选行组数不是实际读取量；尚未分离裁剪、解码、缓存、固定查询开销等因素。
9. 10% 和 20% 均为人为约定。达到 10% 不是统计显著、也不是实际业务一定值得投入；阈值改变，分类也会改变。
10. 两次预试验在 C 盘，正式数据位于 E 盘；不能假定盘符变化就是物理硬盘变化，也不能把差异直接归因于硬盘。
11. 预测误差是事后补充复核；正式阶段未冻结唯一预测表，不能夸大事前预测能力。
12. 观察到的次数是离散测点，不假装通过插值测到了 27 或 35 次。

## 五、是否需要补充：供讨论，不执行

现有工作超过了单纯展示“排序后更快”的演示，具有明确的场景化经验问题和配对数据。但它的技术新颖性仍有限：已知原理预期能解释主要方向，目前最薄弱的是只比较两个窗口长度、且没有覆盖同长度不同边界位置，所以尚未形成一个不显然的机制结论或自己的技术改进。

如果按课程所允许的“独立实验验证”定位，可以用现有内容写成诚实的小范围报告，不必为了创新而硬造算法。但如果希望原创探索更有说服力，建议只讨论一项最小补充：**固定 1 天窗口，比较位于一个行组内和跨越两个行组边界的查询，观察原先回本与 10% 达标判断是否改变。**

建议的补充规则（尚未冻结或执行）：

- 不改原始数据、布局、软件环境或已有结果。
- 根据已存在的行组时间范围选择窗口，而不是看查询耗时后挑有利例子；事先写清取样规则。
- 两类窗口长度一致、实际命中记录数尽量相近，并记录差异；各选多个起点，避免一个窗口代表一类。
- 先固定少量查询次数和配对重复规则，保留相同的 0%、10% 定义；补充任务单独编号，不替换本轮结果。
- 这项补充要回答的是“同样查一天，边界位置是否改变收益判断”，不是再展示一次排序更快。
- 如果无差异，接受“在所测范围内未观察到明显边界效应”；如果有差异，才讨论把边界覆盖纳入基准测试窗口选择的改进建议。

只补算 5%、10%、15% 门槛也能说明分类敏感性，但属于低成本的事后分析，对技术原创性提升较小；无需扩大到多引擎、多机器、真实 AIS 数据或自动选择器。
