## 实际环境与测试材料

- Windows x64；Python 3.12.14。独立创建虚拟环境，不继承项目 `.deps`。
- 从项目文件构造不含 `data/`、`.deps`、`.cache` 的下载式副本；再创建路径含中文与空格的隔离副本。没有实际 Git clone，因为仓库尚未创建。
- 按历史 `requirements.txt` 安装三项依赖，pip 自动解析其余依赖；记录为 `requirements-repro-v2.txt`，再用该文件确认安装环境，`pip check` 通过。
- 首次 pip 请求受执行沙箱网络限制失败；获准联网后安装成功，日志显示使用本机 wheel 缓存。本轮没有证明无缓存下载可用，也没有安装或升级原实验 `.deps`。
- 本轮依赖锁只描述本轮复现环境。历史 Python、DuckDB 等仍按原配置记录；不能用本次环境倒填历史未记录项。

## 路径处理与追踪

历史配置保留旧绝对路径及哈希，不重写证据。`verify-history` 将已知 `data/`、`results/` 后缀映射到当前根目录，只读当前目录内的对应文件；数据缺失会明确说明，不回退访问旧 E 盘。新 prepare 基于副本内路径重新冻结；准备后移动副本仍需重新 prepare 新 ID，不能手工改旧冻结配置。

根目录历史 `*.py` 的字节不变。新入口单独放在 `tools/reproduce_v2.py`；副本 `replay_v2.json`、`replay_logs/` 和补充 `interface_v2.json` 记录来源与接口／脚本哈希。历史流程的数学定义、种子、次数、计时边界不通过新入口调整。
